# 07 · Embodiment interface specification

[中文](/07-pet-bridge) | English

The pet is not the agent's skin. It is the embodiment layer for a `GateSignal`. The interface is
defined between the engine and the pet runtime, decoupled from any specific implementation
(dsh-pet / OpenPets / anything else).

## Engine → pet: `gate_signal`

```yaml
id: uuid
policy_id: string
decision: suggest | require_approval | suppress        # note: never allow
presentation:
  animation_hint: idle_shift | stretch | alert | thinking
  bubble_text: string          # at most 30 characters, from the policy
  actions:
    - label: Approve
      action_id: approve
    - label: Ignore
      action_id: dismiss
    - label: Silence for 1 hour
      action_id: mute_1h
action:                        # declared intent, not an executed action
  type: suppress_notifications
  scope: [slack, mail]
  parameters: { duration_minutes: 50 }
escalation:
  after_minutes: 10
  action: remind_once
  decision: suggest
expires_at: ISO8601 | null
created_at: ISO8601
trigger_event_id: string       # for tracing; contains no window content
audit_level: full | summary | none
```

Schema: `schemas/signal.schema.json`. Invariants are enforced at construction by `validateSignal()`:

- `bubble_text` is at most 30 code points (CJK counts as one character);
- `decision: require_approval` must offer at least one non-`approve` action — **refusal must be possible**.

## Pet → engine: `gate_response`

```yaml
signal_id: uuid
action_id: approve | dismiss | mute_1h
responded_at: ISO8601
```

Only these three actions are legal. A pet cannot invent actions, and it cannot answer with just a
`policy_id`: it must return the exact `signal_id` that was presented, or the engine raises
`unknown_signal`.

## Interaction constraints (fixed, so a pet cannot become a nuisance)

1. One policy is presented at most once per `escalation.after_minutes` window (default 30 minutes);
2. No automatic retry after a user `dismiss`;
3. The pet must not pop up unprompted while the user is in a `focus_block` with no matching policy;
4. Every `require_approval` signal must include at least one "refuse" action;
5. Pet animation and bubble copy **must not be generated by an LLM at runtime**; they come from the policy's `presentation` field, which keeps them auditable and testable.

Constraints 1 and 2 are implemented by the `AgentGate` rate limiter and `mute` state machine;
constraint 4 by `validateSignal`; constraint 5 by there being no generation entry point in a signal at
all.

How constraint 5's "from the policy" is honoured differs between the two embodiment surfaces, and
that split is deliberate:

- **The DSH composer** renders `animation_hint` as a static marker keyed by the enum (four Unicode
  glyphs, set through `data-animation`); `verify-client.mjs` asserts it renders, carries the policy's
  value, and stays hidden from screen readers.
- **OpenPets** does *not* consume `animation_hint`: `pet.react` takes a closed reaction enum, and
  which sprite a reaction plays belongs to the desktop app, user-overridable in Control Center. The
  published contract defines no hint→reaction translation, so inventing one would fight that
  ownership. The stance is recorded in `map.ts` and the adapter README instead of dropping the field
  silently.

In other words: **a contract field is never dropped in silence** — either it is rendered, or the
surface states that it does not apply.

## HTTP bridge (`gate pet`)

Listens on `127.0.0.1:3778` by default and binds loopback only.

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/healthz` | `{status, engine_version, policy_count}` |
| `POST` | `/v1/events` | body `{event}` (a bare event is also accepted); returns the evaluation result |
| `GET` | `/v1/signals/pending` | Unanswered, unexpired signals |
| `POST` | `/v1/signals/:id/respond` | body `{action_id, responded_at}` |

Errors are returned as `{error: {code, message, retry_after_seconds?}}`:

| Status | Situation |
| --- | --- |
| 400 | Malformed event or response body, or a JSON parse failure |
| 404 | Unknown `signal_id`, or the signal does not offer that action |
| 429 | Event submission rate limited (60 per minute by default) |

Tests override the server clock with the `X-Agent-Gate-Now` header. It drives the evaluation instant
(`time_window` / `day_of_week`), the rate limiter and expiry alike, so replaying historical events is
reproducible.

## Wiring a pet host

The engine exports a client so an adapter does not re-implement the protocol:

```ts
import { PetBridgeClient } from 'agent-gate/pet';

const client = new PetBridgeClient({ baseUrl: 'http://127.0.0.1:3778' });

// Fires once per signal id, even though the bridge returns the same pending
// signal on every poll.
const poller = client.onSignal({
  interval_ms: 1000,
  onSignal: (signal) => {
    show(signal.presentation.bubble_text);       // policy copy, verbatim
    render(signal.presentation.actions, (actionId) => client.respond(signal.id, actionId));
  },
});

// later: poller.stop()
```

The client refuses a non-loopback `baseUrl` unless you pass `allow_remote: true`.
That default matters: the bridge dispenses approval prompts, so pointing an
adapter at someone else's host should be a deliberate act, not a typo in a port.

### A shipped adapter

`integrations/dsh-agent-gate-pet/` is a working DeepSeek Harness bundle that does
the above: a host half that proxies the bridge through loopback-only routes, and
a browser half that renders each signal in the composer dock. It is a separate
bundle and shares no code with any pet plugin.

It is deliberately *not* grafted onto `dsh-hackmagic-pets`: that package renders a
3D pet and exposes no bubble or animation hook, so an adapter inside it would have
meant editing its prebuilt client bundle — the host kernel by another name.

### A second embodiment: OpenPets

`src/pet/openpets-adapter/` targets [OpenPets](https://docs.openpets.dev), a
desktop companion app with its own integration contract. It is a separate
adapter rather than a variant of the one above, because the two hosts disagree
on the important parts: OpenPets routes pets through leases, takes a closed
reaction enum instead of animation hints, and constrains speech to curated
pools.

| Contract clause | How this adapter satisfies it |
| --- | --- |
| Configuration is reversible | Marked entries, byte-exact backups, refusal of foreign files |
| Runtime is fire-and-forget | `dispatch()` never awaits or throws; failures land in `stats()` |
| Speech is always safe | Messages come from curated pools, never from `bubble_text` |
| Leases route the pet | 15s TTL, heartbeat with stale-id recovery, single release |

Its README (`src/pet/openpets-adapter/README.md`) records the details and the
failure states; `tests/openpets.test.ts` proves all four clauses without a
running app.

```bash
node integrations/dsh-agent-gate-pet/test/verify-host.mjs
node integrations/dsh-agent-gate-pet/test/verify-client.mjs
```

The key point stands in both the sketch and the shipped bundle: **the embodiment
never silences notifications itself.** It sends the `action_id` back, and a
user-space adapter performs the action — the engine only records the decision and
the response.

## Acceptance criteria

> Trigger a `require_approval` policy by hand; the pet shows the prompt, and after the user approves,
> the audit log records the whole chain.

Location: `tests/pet.test.ts`, `tests/pet-client.test.ts`, and
`integrations/dsh-agent-gate-pet/test/`

- Initial `healthz` / `pending` state
- Event → signal → visible in `pending` → `approve` → `pending` empty
- After `dismiss`, the same policy does not retry (`throttled: true`)
- Unknown signal 404, bad JSON 400, rate limit 429
- The shipped adapter: loopback fence on every route, an invented action refused before it reaches the engine, an unreachable bridge rendered as a state rather than a crash
