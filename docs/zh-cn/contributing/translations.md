# 参与翻译

[English](../../en/contributing/translations.md) | 中文

**中文是唯一真值源**，包括英文在内的其他语言都是对它的本地化。本页讲清流程、边界，以及评审者会检查什么。

仓库的对外门面仍然是英文：`README.md` 是英文、`README.zh.md` 是它的中文副本，因为 GitHub 访客先读英文。
`docs/` 内部的顺序相反——先写中文。

## 目录结构

```text
docs/
├── zh-cn/       真值源，先写这里
├── en/          翻译，逐页镜像 zh-cn/
└── i18n/        配对记录（生成的，不要手改）
```

两棵树使用**完全相同的文件名**。`docs/zh-cn/` 里有的页面，`docs/en/` 里必须有同名页面。
缺页、标题大纲不一致、只改了一边，`npm run verify-i18n` 都会失败。

仓库根目录的页面（`README.md`、`CONTRIBUTING.md`）保留并列形式，因为工具与托管平台要从根目录读它们。

## 两条要紧的规则

### 1. 翻译散文，绝不翻译标识符

| 要翻译 | 不翻译 |
| --- | --- |
| 正文、标题、描述 | 代码、变量名、配置键、命令 |
| 提示块文案、排障文字 | 参数名、错误码、日志关键字 |
| 贡献指南文字 | 枚举值、接口路径、包名、版本号 |

代码块里的注释可以翻译。代码本身不能改。

### 2. 翻译不能改变含义

翻译可以：

- 本地化表达——把长英文句拆成短句，用母语开发者习惯的说法；
- **不能**新增英文页面里没有的教程；
- **不能**删减或弱化 Warning / Caution；
- **不能**改写所描述的行为；
- **不能**扩写或压缩信息量，含义必须等价。

如果中文页面写错了，就改中文页面。不要只在翻译里修：那样翻译会变成唯一正确的副本，
而下一次同步会把修好的内容覆盖掉。

## 流程

1. **先改中文页面。** 任何内容变更都从那里开始。
2. **跑门禁。** `npm run verify-i18n` 会报出哪些不同步。
3. **翻译。** 用同样的结构更新 `docs/en/`。
4. **重新记录。** `npm run verify-i18n -- --write` 更新配对哈希。
5. **一个 PR。** 中文改动与翻译放在一起，标题用 `docs:`。

中文里不存在的页面，其翻译会被拒绝，而不是先合并再补。两棵树在任何一次提交上都必须可比。

## 翻译状态

每个翻译页面声明自己的完成度：

| `translation_status` | 含义 | 读者看到什么 |
| --- | --- | --- |
| `complete` | 完整翻译并已评审 | 译文 |
| `partial` | 部分章节仍是英文 | 混合，未翻部分保持英文 |
| `todo` | 尚未开始 | 英文原文，或什么都没有 |

标 `partial` 的页面，未翻的章节必须保留英文，而不是机翻过去。一条 Warning 的粗糙翻译，
比不翻译更糟。

## 评审者检查什么

翻译 PR 对照的是英文原文，不是译者的意图。

- [ ] 英文里存在该页面，且文件名相同
- [ ] 标题大纲逐节对应
- [ ] 没有标识符被翻译（`GateSignal`、`require_approval`、`action_id` 等）
- [ ] 没有 Warning / Caution 被删或被弱化
- [ ] 没有新增英文页面没有的内容
- [ ] 术语与[术语表](../glossary.md)一致，没有使用同义词
- [ ] `translation_status` 与实际相符
- [ ] `npm run verify-i18n` 通过
- [ ] 链接在翻译树内可解析
- [ ] 除注释外，代码块与英文页面逐字节一致

## 什么情况下不要提交翻译

- **中文页面正在变动。** 翻译一个正在重写的页面，合并时就已经过期了。等中文改动落地。
- **你只能靠猜。** 术语表里没有、中文本身又有歧义时，先在中文页面上提问。
  一个靠猜的契约术语译文，是会活过评审的缺陷。
- **这是事实而不是表达。** 数字、默认值、错误码、版本范围属于中文源；不要在翻译里「修正」它们。

## 机翻

机翻可以作为初稿，绝不能作为终稿。这样的页面在人工通读之前一律标 `translation_status: partial`，
永远不要标 `complete`。

具体风险是：机翻会翻译散文里的标识符、把 Warning 降格成从句、把 `must` 译成建议。三者都是契约损伤。

## 标签

| 标签 | 用途 |
| --- | --- |
| `docs` | 仅文档改动 |
| `i18n` | 翻译，或翻译工具链的改动 |
| `i18n:zh-cn` | 具体触及的语言 |

## 新增一种语言

1. 先加术语表：`docs/&lt;lang&gt;/glossary.md`，从[中文术语表](../glossary.md)翻译。
2. 建 `docs/&lt;lang&gt;/` 树，镜像页面清单。
3. 扩展 `scripts/verify-i18n.mjs` 让它认识新树——脚本目前把 `en` 与 `zh-cn` 显式配对，
   新增语言就要在那里加。
4. 框架文案（侧边栏、搜索、版本选择器）走文档站点的 i18n 配置，绝不在正文里硬编码。
