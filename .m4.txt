fix(packs): two policies fired in the wrong situation

Walked both packs with real event sequences. Two of the eight policies
behaved in a way the copy did not support.

`long-stretch-break` fired at 22:00 and 02:00. "坐满一小时了，伸个懒腰？" is
the wrong thing to say when someone is finishing the day rather than
mid-afternoon, and `late-night-work` already asks a different question there.
It now has an 08:00-21:00 window.

`context-thrash-warning` fired on *any* evening switch. Its condition was
`any: [duration < 120, time_window 21:00-23:59]`, so the second branch ignored
duration entirely — including switching back into the editor after a 15-minute
stay. Both branches now require a short dwell (120s by day, 300s in the
evening), and the copy says what it now means: "这个应用只待了两分钟？".

Both are version 2, since behaviour changed.

Eleven example sequences are now fixtures in `examples/*-sequences.json`,
recording what each case is supposed to do. `npm run verify-examples` replays
them and fails when a YAML edit changes an outcome — a fixture nobody checks
is a stale expectation, not a test. The same replay also runs inside
`npm test`.

Deliberately not changed: `focus-switch-ask` still fires when leaving the
editor after a minute. That is a short dwell like any other, and the pack's
premise is that fragmented switching is worth naming regardless of the app.
